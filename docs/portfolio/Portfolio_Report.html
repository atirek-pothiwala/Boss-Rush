Boss Rush — Student Portfolio Report

Track: Game Development and Simulation  |  Engine: Unity 6 (6000.4.3f1)  |  Live Demo: atirek-pothiwala.github.io/Boss-Rush

Project Overview

Boss Rush is a 2D side-view fighting game where the player selects one of three heroes and fights through a sequence of three bosses: Minotaur, Werewolf, and Gorgon. Each boss has unique attack patterns, animations, and battle music. The player manages health and stamina, blocks with a shield, and exploits openings after boss attacks to win.

A full run takes approximately 8–12 minutes (three boss encounters with save/resume). The project demonstrates scalable Unity architecture, data-driven combat, animator-driven boss AI, and polished WebGL deployment.

Features

  • Three playable heroes (Samurai, Shinobi, Fighter) with distinct stats
  • Three bosses with unique behaviours and enrage phases (below 50% HP)
  • Health and stamina systems for player and boss
  • Combat: quick/power/special attacks, shield, jump, run
  • Boss AI: approach, attack by range/stamina, retreat, enrage
  • Save/resume progress; settings for music and SFX volume
  • Pause, restart, exit to menu; victory and defeat screens
  • WebGL deploy with landscape layout and mobile rotate prompt

Techniques Used

  • Single-responsibility managers — Dashboard, Level, Health, UI, Pause, Sound, Camera
  • Data-driven combat — PlayerAttackConfig and BossAttackConfig on prefabs
  • Animator state machines — PlayerState / BossState enums drive animation
  • Unity Input System — keyboard + gamepad via event-based PlayerInputManager
  • Canvas Scaler — 1280×720 landscape UI with runtime-built menus
  • SceneTransition — deferred loads for WebGL stability
  • EditMode tests — save/load, constants, boss animator validation
  • CI/CD — GitHub Actions compile + WebGL deploy

Challenges

  • Boss animator misconfiguration (Minotaur idle freeze) — prefab audit + failsafe recovery
  • WebGL null function on scene change — deferred loading + event cleanup
  • Escape pause required hold — fixed PressAndRelease input interaction
  • Mobile layout — landscape lock and canvas scaler tuning
  • Singleton lifecycle during scene unload — null guards and OnDestroy cleanup

Future Improvements

  • Fourth boss / hard mode; attack telegraphs; achievements
  • Object pooling for VFX; more automated combat tests
  • Gamepad UI navigation; localisation
